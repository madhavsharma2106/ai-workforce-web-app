# Component Architecture

How `src/components/` is organized, and how to extend it without drifting back into copy-pasted Tailwind.

## Structure (atomic design)

```
src/components/
  atoms/        pure, single-purpose UI primitives — no business logic, no data fetching
  molecules/    small compositions of 2+ atoms — only exist where a pattern genuinely repeats
  organisms/    feature components (AuthGate, LeadCard, ConversationalForm, LeadSourcerHome) — own domain logic, compose atoms/molecules
```

Pages under `src/app/` (the landing page, `/dashboard`, `/employee/[id]`, `/employee/[id]/onboarding`) compose organisms; organisms compose atoms/molecules. Import via the barrels: `@/components/atoms`, `@/components/molecules`, `@/components/organisms/<Name>` (organisms aren't barrel-exported from a single index — import each by name).

Authenticated routes (`/dashboard`, `/employee/[id]` and its subroutes) live under the `src/app/(app)/` route group, which shares one `layout.tsx` — it does the signed-in check and renders `AppHeader` once, instead of every page importing it. The landing page and `/login` sit outside this group and render their own chrome (or none).

## Atoms (`src/components/atoms/`)

| Component            | Props                                                                                                                                                                                   | Notes                                                                                                                                                                                                                                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Button`             | `variant?: "primary" \| "secondary" \| "danger" \| "accent"`, `size?: "sm" \| "md" \| "lg"`, `fullWidth?: boolean`                                                                      | `primary` (leaf green) is the default and the main CTA color — the system's one accent hue, not reserved for rare emphasis. `secondary` is a pale sage pill; `danger` reuses the same pale pill with red text (see [DESIGN.md](DESIGN.md)).                                                                |
| `Input` / `Textarea` | native attrs + `className`                                                                                                                                                              | Share one base field style — borderless, filled with the inset tone.                                                                                                                                                                                                                                       |
| `Card`               | `as?: ElementType` (default `div`), `padding?: "none" \| "sm" \| "md" \| "lg"` (default `lg`)                                                                                           | Owns shape and background (`rounded-[20px] bg-(--surface)`, no border, no shadow). Callers can still override background via `className` for the rare non-white card (e.g. an inset-toned card).                                                                                                           |
| `Badge`              | `tone?: "neutral" \| "accent" \| "success" \| "warning" \| "danger"`, `size?: "xs" \| "sm" \| "md"`                                                                                     | Status pills, tags. Tones map to pale tints of the one accent hue except `danger`, which is the literal red exception.                                                                                                                                                                                     |
| `Eyebrow`            | `tone?: "accent" \| "accent-faint" \| "muted"`, `tracking?: "wide" \| "widest"`                                                                                                         | The small-caps kicker/label pattern from [DESIGN.md](DESIGN.md).                                                                                                                                                                                                                                           |
| `Heading`            | `as?: ElementType` (default `h2`), `size?: "xl" \| "lg" \| "md" \| "sm"`, `italic?: boolean`                                                                                            | Serif (Lora) headings, regular weight by default. `italic` is reserved for the Emma-voice greeting/headline treatment — an employee speaking first-person about their own work — not generic section headings.                                                                                             |
| `Text`               | `as?: ElementType` (default `p`), `size?: "xs" \| "sm" \| "md" \| "lg" \| "xl"`, `tone?: "default" \| "muted" \| "subtle" \| "inverted"`, `weight?: "normal" \| "medium" \| "semibold"` | General body/paragraph text.                                                                                                                                                                                                                                                                               |
| `EmployeeAvatar`     | `seed: string`, `size?: "sm" \| "md" \| "lg"` (32/40/56px)                                                                                                                              | Wraps `boring-avatars` (`variant="beam"`, `square`), seeded on `employee.id` for a deterministic, unique-per-employee avatar, clipped into the organic "blob" radius via a wrapping div. Colors constrained to the Greenhouse palette instead of the library's default rainbow — see `EmployeeAvatar.tsx`. |
| `Breadcrumb`         | `items: { label: string; href?: string }[]`                                                                                                                                             | Crumbs without `href` render as the current (non-linked) page. Used on `/employee/[id]` and its `onboarding`/`chat` subroutes to orient the user back to `/dashboard`.                                                                                                                                     |
| `Modal`              | `open: boolean`, `onClose: () => void`, `children`                                                                                                                                      | Centered `Card` over a click-to-dismiss backdrop; closes on Escape too. No built-in header/footer chrome — callers compose that from `Heading`/`Text`/`Button` in `children` (e.g. `KnowledgeRefreshModal`).                                                                                               |
| `Tabs`               | `tabs: { key: T; label: string }[]`, `activeKey: T`, `onChange: (key: T) => void`                                                                                                       | Generic over the tab-key union `T` so callers get a typed `activeKey`/`onChange` rather than a bare string. Controlled — owns no state itself.                                                                                                                                                             |
| `LocalDate`          | `date: string`, `options?: Intl.DateTimeFormatOptions`                                                                                                                                  | Renders a timestamp in the viewer's local time zone: server-rendered in the server's zone first, then corrected pre-paint via `InlineScript` (see that component's own comment on the flash-of-wrong-time problem this avoids).                                                                            |
| `InlineScript`       | `html: string`                                                                                                                                                                          | Injects a `<script>` that runs synchronously during HTML parsing, before first paint — used by `LocalDate` for its time zone fix. Not a general-purpose primitive; reach for it only when something genuinely needs to run pre-hydration.                                                                  |

`cn(...)` (in `atoms/cn.ts`) is a tiny classname-joiner (`filter(Boolean).join(" ")`) — no `clsx`/`tailwind-merge` dependency.

## Molecules (`src/components/molecules/`)

| Component  | Built from                                           | Used for                                                                                                                                        |
| ---------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `Alert`    | `variant?: "info" \| "error"`                        | Inline banners (search-in-progress, error messages, "check your email").                                                                        |
| `Markdown` | `react-markdown`, wraps `Heading`/`Text` per element | Renders founder-editable markdown (Business Profile, employee Instructions) with this app's type styles instead of `react-markdown`'s defaults. |

A `Field` molecule (label + input) was considered during the initial extraction but dropped — at the time there was only one real call site (`LeadCard`'s draft-email textarea), and a molecule with a single consumer is premature abstraction. Revisit if a second genuine label+field duplicate shows up.

## Design tokens

CSS custom properties live in `src/app/globals.css` — surfaces (`--background`, `--surface`, `--inset`), the single accent hue (`--accent`, `--accent-hover`, `--accent-soft`, `--accent-soft-2`), text (`--heading`, `--body`, `--body-strong`, `--muted`, `--muted-faint`), and button/misc tones (`--secondary-bg`, `--disabled-bg`, `--avatar-neutral`, `--border`). Atoms reference them with Tailwind v4's canonical arbitrary-var syntax, e.g. `bg-(--inset)`, `text-(--heading)` — not the older `bg-[var(--inset)]` form. Colors with no matching token (e.g. `red-*` for danger/reject states) stay as literal Tailwind classes inside the primitive's variant definition — don't invent new tokens to chase 100% token coverage. See [DESIGN.md](DESIGN.md) for the full palette and shape scale ("Greenhouse").

## One-off overrides

Tailwind's generated CSS order isn't guaranteed to follow JSX `className` order, so a caller-supplied override on the same CSS property as a variant's built-in class (e.g. shrinking a `Button`'s padding, or forcing `Badge`'s background to white) can silently lose. Use the important-modifier suffix for a guaranteed win, e.g. `className="px-4!"` or `className="bg-white!"`. Reference usages: the "Approve all" button and "Emma is learning" badge in `src/app/page.tsx`.

## Extending this

- **New variant on an existing atom**: only add one backed by a real call site in the app — don't pre-populate options nobody uses yet.
- **New atom**: only when a class-string pattern is duplicated 2+ times across files (grep before assuming).
- **New molecule**: only when 2+ real call sites compose the _same_ atoms in the _same_ shape.
