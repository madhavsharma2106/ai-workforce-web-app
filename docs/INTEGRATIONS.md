# Integrations

Third-party data sources and services AI employees pull from. Each integration is a single file under `src/lib/integrations/` exporting typed functions — no shared base class (see PRINCIPLES.md: don't abstract until a second integration proves what's shared).

| Integration               | File                                     | Used for                                                                                                                                                                                                                                                                                                                                                                                                                           | Env var                                                                                           | Used by                                                                                                                                                                                                                                                                                                              |
| ------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Apollo.io                 | `src/lib/integrations/apollo.ts`         | Lead search (`searchPeople`), per-candidate enrichment to resolve real company identity (`enrichPerson`, run on every result), and email reveal (`revealEmail`)                                                                                                                                                                                                                                                                    | `APOLLO_API_KEY`                                                                                  | Lead Sourcer, via the `search_leads` tool (`src/lib/agents/tools/searchLeadsTool.ts`) and `src/app/api/leads/reveal-email`                                                                                                                                                                                           |
| Company websites          | `src/lib/integrations/companyWebsite.ts` | Fetches and cleans a company's homepage text for the model to reason over (`fetchCompanyText`) — not a distinct third-party product, just plain `fetch` against whatever domain Apollo returned                                                                                                                                                                                                                                    | none                                                                                              | Lead Sourcer, via the `search_leads` tool (`src/lib/agents/tools/searchLeadsTool.ts`)                                                                                                                                                                                                                                |
| Anthropic Claude          | `src/lib/agents/model.ts`                | Powers all employee reasoning and tool-use (MVP; provider is swappable — see [AGENTS.md](AGENTS.md))                                                                                                                                                                                                                                                                                                                               | `ANTHROPIC_API_KEY`                                                                               | Every employee, via `src/lib/agents/runTurn.ts`                                                                                                                                                                                                                                                                      |
| Outlook (Microsoft Graph) | `src/lib/integrations/email/outlook.ts`  | Sending approved outreach from the founder's own mailbox, saving a draft into their real mailbox Drafts folder without sending, polling the inbox for replies on sent threads, and sending threaded replies (all OAuth-delegated, so every action acts as the founder — see [roles/sales-representative.md](../roles/sales-representative.md)); connected via `/settings`, tokens stored in Supabase Vault (`mailbox_connections`) | `MICROSOFT_CLIENT_ID`, `MICROSOFT_CLIENT_SECRET`, `MICROSOFT_TENANT_ID`, `MICROSOFT_REDIRECT_URI` | Sales Representative, via `sendViaConnection`/`saveDraftViaConnection`/`listInboxRepliesViaConnection`/`sendReplyViaConnection` (`src/lib/mailboxConnections.ts`) and the `leads/send-requested`/`leads/save-draft-requested`/`leads/reply-send-requested` Inngest jobs plus the cron-triggered `pollForReplies` job |

Emails go through a provider-agnostic `EmailProvider` interface (`src/lib/integrations/email/types.ts`, `sendMail` + optional `saveDraft`/`listInboxMessagesSince`/`sendReply`) with a registry (`src/lib/integrations/email/registry.ts`) — adding another provider (Gmail, etc.) later is a new file + one registry entry, not a rewrite of the send flow. `saveDraft`, inbox reading, and replying on Outlook all need the `Mail.ReadWrite` scope in addition to `Mail.Send` — founders who connected before this scope was added need to reconnect. `sendMail` creates the message via `POST /me/messages` before sending it (rather than the simpler `POST /me/sendMail`) specifically to capture the Graph `conversationId` it returns, which is what `pollForReplies` later polls against — see [AGENTS.md](AGENTS.md) for the reply-monitoring flow. Reply monitoring polls every 5 hours (cron, not a webhook) and only tracks threads Oliver actually sent through the app; obvious auto-replies/bounces/OOO messages are filtered out before they ever reach a model call.

Add a row here whenever a new integration file is added.
