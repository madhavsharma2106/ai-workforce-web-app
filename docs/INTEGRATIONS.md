# Integrations

Third-party data sources and services AI employees pull from. Each integration is a single file under `src/lib/integrations/` exporting typed functions — no shared base class (see PRINCIPLES.md: don't abstract until a second integration proves what's shared).

Emails go through a provider-agnostic `EmailProvider` interface (`src/lib/integrations/email/types.ts`, `sendMail` + optional `saveDraft`/`listInboxMessagesSince`/`sendReply`) with a registry (`src/lib/integrations/email/registry.ts`) — adding another provider was a new file + one registry entry, not a rewrite of the send flow, which is how Gmail was added alongside Outlook. `saveDraft`, inbox reading, and replying on Outlook all need the `Mail.ReadWrite` scope in addition to `Mail.Send` — founders who connected before this scope was added need to reconnect. `sendMail` creates the message via `POST /me/messages` before sending it (rather than the simpler `POST /me/sendMail`) specifically to capture the Graph `conversationId` it returns, which is what `pollForReplies` later polls against — see [AGENTS.md](AGENTS.md) for the reply-monitoring flow. Reply monitoring polls every 5 hours (cron, not a webhook) and only tracks threads Oliver actually sent through the app; obvious auto-replies/bounces/OOO messages are filtered out before they ever reach a model call.

Gmail needs only the single `gmail.modify` scope for all four operations (Google's per-method scope docs list it as sufficient for `messages.send` and `drafts.create`, not just reading). Because the Gmail API works with raw RFC 2822 messages rather than a JSON body like Graph, `gmail.ts` builds and base64url-encodes the MIME message itself, and threads replies by carrying forward the original message's `Message-ID`/`References` headers (plus `threadId`) rather than relying on a dedicated reply endpoint. `mailbox_connections` has one row per founder (`user_id` is uniquely constrained on its own, not `(user_id, provider)`), so connecting Gmail replaces an existing Outlook connection rather than adding a second mailbox — a founder has at most one connected mailbox, on either provider, at a time. Gmail's `gmail.modify` scope is a Google "restricted" scope: while the OAuth consent screen is in Testing status only test users added on that screen can connect (see `.env.example`).
